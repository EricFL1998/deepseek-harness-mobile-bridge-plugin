ci: rebuild the rootfs image after publishing a release

A new plugin version should reach fresh installs bundled, not only existing
devices through the in-app update. After the version-marker release is created,
dispatch `bridge-release` to the rootfs repository so it rebuilds.

The dispatch needs ROOTFS_DISPATCH_TOKEN, a token with contents:write on the
rootfs repository, because a repository_dispatch into another repository cannot
use this one GITHUB_TOKEN. When the secret is absent the release still publishes
and the step warns instead of failing: existing devices are unaffected, and the
next rootfs build picks the version up.
